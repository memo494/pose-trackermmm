## Decisions (lead, measured on the reference model)
1. **A tentative track survives `trackTentativeMaxMisses` (1) missed frames** instead of dying on the first.
   Reference model, one person at score 0.4 whose detection is missing in a fraction p of the frames, 20 fps,
   40 seeds: time until the ring is shown, p90, from 1050 to 600 ms at p = 0.4 and from 2650 to 1450 ms at
   p = 0.6; S1, S9 (one-frame and two-frame false positives), S12 and S13 unchanged
   (`docs/plans/M4_sim/tentative.py`). The hit counter is not reset by a miss; a hit resets the miss counter.
2. **A display smoother on top of the tracker:** a OneEuro filter per shown track on the head point (x, y), in
   Img px, cutoff `fc = smoothMinCutoffHz + smoothBeta · |speed| / h` (speed of the filtered derivative in
   px/s, `h` the track's height), derivative cutoff `smoothDerivativeCutoffHz`. Defaults **1.0 Hz, 3.0,
   1.0 Hz**. The box is moved with the smoothed head point (its offsets to the head are kept), so ring and
   brackets stay together. Reference model (`docs/plans/M4_sim/euro.py`), 8 seeds: jitter ratio of a still
   person 0.51 → 0.10 at 20 fps and 0.37 → 0.05 at 30 fps; walking lag +0.37 / +0.50 frame; overshoot after an
   abrupt stop ≤ 0.04 h. `smoothEnabled` (default true) turns it off.
3. **Not in M4a** (M4b): forward prediction, fading LOST tracks, tap-to-lock, the tuning sheet.

## Tasks (sequential; agent = implementer)
### T1 — Core: tentative miss tolerance · S
`TrackerConfig.trackTentativeMaxMisses` (Int, default 1, bounds 0..5, KDoc, test). `Tracker`: a tentative
track that misses keeps living while its consecutive misses ≤ the setting (it coasts like a lost track: no
`lostMs`, velocity decay as for a miss; it is not shown and not LOST); a hit resets its miss counter; with 0 the
behaviour is exactly today's. Tests first (`TrackerTest`): tolerance 0 = today; tolerance 1 survives one miss and
confirms on the third hit; two misses in a row remove it; a hit-miss-hit-miss-hit person is shown. New scenario
**S15** in `TrackerScenarioTest`: one walking person (`scenarios.py`-style, score 0.4, each frame dropped with
probability 0.4 by `java.util.Random(seed·13+1)`, one `nextDouble()` per frame from frame 0): shown within
`S15_MAX_FIRST_SHOWN_MS` = 1000 ms at every rate and seed 1–3 (new constant in `MetricsThresholds.kt`, KDoc
"model p90 600 ms at 20 fps"; adding constants to the protected file is allowed by this task, changing existing
ones is not). All existing scenarios stay green unchanged.
### T2 — Core: `HeadSmoother` · M
`core/tracking/HeadSmoother.kt`: per-id OneEuro state for up to `maxTracks` ids (pool, allocation-free),
`apply(snapshotTracks: TrackList or the snapshot builder input, timestampNs)` producing smoothed head x/y per
shown track; first sample of an id passes through; an id not shown in a frame frees its slot; `reset()`.
Config fields `smoothEnabled`, `smoothMinCutoffHz`, `smoothBeta`, `smoothDerivativeCutoffHz` (KDoc, units,
bounds, tests). Tests first: a constant input stays constant; a step converges; jitter ratio on seeded noise
(still, 20 fps) ≤ 0.2; lag on a constant velocity ≤ 0.6 frame at 20 fps; overshoot after a stop ≤ 0.05 h;
`dt ≤ 0` leaves the state; ids freed and reused correctly; disabled = identity.
### T3 — App: smoothed snapshot · S
`FramePipeline` (capture thread) runs the smoother between `tracker.update` and `TrackSnapshot.of` with the
frame timestamp; the snapshot carries the smoothed head and the box moved by the same delta; `reset()` of the
smoother wherever the tracker is reset; idle republish (`onIdle`) does not advance the smoother. Tests in
`FramePipelineTest`.
